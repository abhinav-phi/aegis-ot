# AEGIS-OT — Design System

> **Version:** 1.0
> **Last Updated:** 20 August 2026
> **Theme:** "Industrial Cyber Command Center" — premium dark SOC/OT aesthetic

---

## 1. Design Philosophy

AEGIS-OT's visual identity communicates **industrial cybersecurity, critical infrastructure, trust, observability, and controlled automation**. The "Industrial Cyber Command Center" theme uses a deep graphite-black canvas with phosphor-cyan infrastructure accents and amber/crimson safety semantics — the look of a plant-floor SCADA display interpreted with modern SOC polish.

Every screen answers three questions for the operator:
1. **What is happening?** (live telemetry, anomaly timeline)
2. **Why?** (attribution bars, explanation panel, evidence)
3. **What may I safely do about it?** (recommendation, validator verdict, approval gate)

### Core Principles
1. **Dark-first, command-center layout** — a persistent left rail (plant groups / incidents) + central working area. No white surfaces except chart backgrounds where contrast demands it.
2. **Cyan = infrastructure state** (telemetry, neutral technical data, attribution).
3. **Amber = analyst attention** (medium severity, notes, pending approvals).
4. **Crimson = safety-critical only** (critical severity, blocked actions, denied approvals, danger).
5. **Monospace for every number and ID** — sensor streams, incident IDs, run IDs, timestamps: `font-mono`.
6. **Autonomy is always visible** — anything the system did on its own carries an explicit badge: `SIMULATED`, `VALIDATOR`, `AUTO`, `AWAITING APPROVAL`. Nothing is silent.
7. **Deliberate motion** — pulses for live signals, page fade-ins; no decorative loops.

```
├───────────────┬────────────────────────────────────────────┤
│ Left Rail     │                                            │
│ (240px)       │         Main Working Area                   │
│ › Dashboard   │  (p-5, scrollable)                          │
│ › Incidents   │                                            │

│ › Demo · Audit│                                            │
│ › Eval · Data │                                            │
│ Liveness dot  │                                            │

└───────────────┴────────────────────────────────────────────┘
```
- Top bar: sticky, `bg-panel/90` blur, bottom border `--line-default`.
- Left rail: `bg-panel`, right border `--line-default`; nav item = 38px row, radius `0.5rem`.
- Mobile: rail collapses to overlay; grids stack.

### 4.2 Responsive Breakpoints

| Tablet | 768–1024px | Rail hidden, 2-col grids |

### 4.3 Grid System

## 5. Component Specifications

### 5.1 StatCard
- Layout: top row = icon + label; center = value (`font-mono text-2xl`); bottom = delta/detail.
- Variants by semantic color; subtle left border `2px` in variant color when "live".

### 5.2 TelemetryCard (Sensor Stream)
- Header: sensor id `font-mono text-xs` + trend sparkline (Recharts `LineChart`, no axis).
- Body: current value (`font-mono text-xl`) + unit + state chip (`NOMINAL` / `ANOMALY` / `INVAR VIOLATION`).
- Sparkline color: `--text-secondary` normal; `--danger` if window anomalous; `--warn` if contribution > 50%.

### 5.3 StatusBadge (generic)
- Shape: `inline-flex items-center gap-1 px-2 py-0.5 rounded-full text-[0.65rem] font-bold uppercase tracking-[0.12em] font-mono`.
- Variants: `ok` · `warn` · `danger` · `info` · `neutral` (bg `--text-tertiary`/20, text `--text-secondary`).

### 5.4 VerdictBadge (validator)
| Verdict | Style |
|---|---|
| `allow` | `ok` badge + `AUTO`/`VALIDATOR` autonomy chip (Design §1.6 — nothing is silent) |
| `require_approval` | `warn` badge + clock icon |
| `block` | `danger` badge + ban icon |
| `escalate` | `danger` badge + flag icon |

### 5.5 Evidence Chip (RAG citation)
- Pill: `[doc_id · section] tier-badge · score`; click → side drawer "View source".
- Tier colors per §2.4; hovering adds underline; chip carries `font-mono`.

### 5.6 Explanation Card
- Header: "Explanation" + consistency score (if available).
- Body: NL summary (Inter), then structured `Hypothesis · Evidence · Contributing sensors · Invariants` blocks.
- Evidence lines: bullet chips with cite ids; a red "Unverifiable claim" chip appears if the explainer flagged anything without a citation (Rules.md R12).

### 5.7 Attribution Bars
- Horizontal stacked/paired bars per sensor: contribution % (0–100), `font-mono` value right-aligned.
- Top-3 sensors highlighted with `--warn`; remainder `--text-secondary`.
- Animation: width transitions 300ms; bars appear in load order.

### 5.8 Anomaly Timeline (Incident Rows)
- Row: severity badge · incident id `font-mono` · start–end `font-mono` · top sensor chip · status → click opens `/incidents/:id`.
- Live liveness: rows updated by SSE pulse with 400ms `--accent-glow` flash on change.

### 5.9 Agent Reasoning Panel
- Vertical trace: `TOOL CALL` / `TOOL RESULT` / `THOUGHT` / `FINAL` rows.
- Each row: monospace header + collapsible payload (`pre`-style JSONB).
- Citations inline as Evidence chips; untrusted tier rows get a red left-border flag.
- Step counter + step limit progress bar at top.

### 5.10 Validator Panel
- Verdict badge left; check list table: `C1..C5` name · pass/fail/flag chip · short reason.
- On `block`: reason panel with the exact policy rule reference (e.g., `policy/control.yaml L12`).
- On `escalate`: banner with escalation path.

### 5.11 Approval Modal
- Triggered from Approvals queue / demo stepper.
- Contents: plan id + step summary (mono), target + params (mono), validator checks summary, citations, risk-class badge.
- Buttons: `Approve & Simulate` (ok, disabled unless step is sandbox-safe) · `Amend` (secondary) · `Deny` (danger, requires reason textarea).
- Status text: "Action executes ONLY inside simulator."

### 5.12 Attack-the-Agent Demo View
- Stepper (7 steps per AppFlow §4) with step cards: context fixture → naive output → manipulation detected → grounding evidence → blocked action → safe recommendation → approval + simulated execute.
- Each card shows the exact payload snippet in `font-mono` with a `block`-quoted bg; a `FIXTURE` watermark badge on every card. F7 (cyber-physical) fixtures from the automated suite (EVAL-04 / THREAT-03) render as sensor-value tables (zeroing/bias/scaling deltas) — never as free text — whenever surfaced in eval/demo data; F7 is not part of the interactive 7-step demo.
- Bottom comparison table: Naive vs Hardened (recommendation · verdict · unsafe-action sparks · blocked? · executed?).

### 5.13 Tables (generic)
- Header row: `bg-[#0d1219]`, `text-[0.68rem] uppercase tracking-wider text-secondary font-mono`.
- Row hover: `bg-[#161d29]` transition 150ms; `divide-y divide-[rgba(56,224,200,0.07)]`.
- Cell padding `px-3 py-2.5`; `overflow-x-auto` wrapper; empty-state illustration (icon + message + CTA).

### 5.14 Buttons
| Variant | Style |
|---|---|
| Primary (`approve`, `run`) | `bg-[#38e0c8] text-[#0a0e14]` hover `bg-[#8ff5e5]` |
| Secondary | `border border-line-default bg-panel hover:bg-elevated` |
| Danger | `bg-[rgba(248,113,113,0.12)] text-[#f87171] border border-[rgba(248,113,113,0.3)]` |
| Ghost / disabled | `text-secondary` / `opacity-40 cursor-not-allowed` |

## 7. Motion & State

| Case | Behavior |
|---|---|
| Page entry | fade + 8px rise, 240ms ease-out |
| Timeline update | 400ms glow flash on changed row |
| Live dot | `animate-pulse` when worker polling OK |
| Attribution load | staggered 80ms width transitions |
| Modal | scale 0.97→1, 160ms overflow-hidden |
| Autonomy badges | static (never animate — labels are factual) |
| Critical badge | slow 2s pulse, capped at 3 beats |
| Skeleton | `animate-pulse` `bg-[#181f2b]` blocks |

**Loading is mandatory**: any data region renders skeletons until resolved (Design.md §7).

---

## 8. Accessibility & Contrast

- All body text ≥ `#8b97a8` on `#11161f` (≥ 4.5:1 contrast).
- Focus rings: `outline 2px solid rgba(56,224,200,0.6) offset 2`.
- Interactive targets ≥ 36px height.
- Color never the only signal: severity always paired with icon/word (e.g., `CRITICAL` + `AlertTriangle`).

---

## 9. Design Constraints (from Rules.md)

- No white page backgrounds anywhere (Design.md §1.1). Exception: none in OT UI (charts styled dark).
- All ids/codes/scores `font-mono` (Design.md §3).
- Every `SIMULATED`/fixture element carries its badge + watermark (Rules.md R39–R40).
- Inline hex colors banned except in the palette tokens above (Design.md §2).
