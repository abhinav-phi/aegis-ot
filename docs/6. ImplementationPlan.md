## PHASE 1 — DATA + BASELINE (Weeks 1–2)

### 1.1 Environment & Repo
**Files:** `docker-compose.yml`, `pyproject.toml`, `Makefile`, `.env.example`
- Setup monorepo, pinned deps (uv), docker services (postgres, minio, chroma, ollama), CI lint/test skeleton.
- Verify SWaT dataset access + license/usage notes; reserve seed values (Rules.md R22). Decision: **download SWaT once, hash-pin.**

**Deliverable:** `make setup` brings up stack.

### 1.2 Ingestion + Registry (DATA-01/-02/-05/-06)
**Files:** `pipeline/ingest/swat.py`, `wustl.py`, `wadi.py`, `registry.py`
- SWaT normal + attack runs → Parquet in MinIO; hash → `datasets` row.
- WUSTL-IIoT-2021 same (secondary).
- WADI optional stub (DATA-03).

**Verification:** `SELECT count(*)` matches source; sha256 recorded.

### 1.3 Preprocessing (DATA-04/-07/-08)
**Files:** `pipeline/preprocess/*.py`
- Temporal splits (no shuffle), cleaning, z-scoring (train-fit), windower W=60/S=1 to Parquet; `dataset_runs` rows + feature manifest.

**Verification:** leakage test: train dates never overlap test dates; σ/μ from train only.

### 1.4 Baseline Model (DET-02)
**Files:** `pipeline/detect/iso_forest.py`, `scoring.py` (+ `lstm_ae.py` only as a stretch ablation, DET-06)
- Isolation Forest on window stats (the single MVP baseline).
- Threshold τ from validation quantile; scoring + latency capture.

**Verification:** baseline F1 on SWaT test split recorded in MLflow.

### 1.5 Python `tests/` scaffold + docs skeleton
- pytest fixtures for ingestion + scoring; README first-pass; `configs/experiments/*.yaml` templates.

**Phase 1 exit criteria:** `make pipeline-baseline` runs end-to-end on SWaT with recorded metrics.

## PHASE 2 — DETECTION + EXPLAINABILITY (Weeks 3–5)

### 2.1 Proposed Detector: TCN-AE (DET-03/-04/-06)
**Files:** `pipeline/detect/tcn_ae.py`
- Dilated causal-conv autoencoder; per-channel residual decomposition (attribution-ready).
- Registry plumbing: `model_versions`, MLflow checkpoint per run.

**Verification:** F1 vs baseline table; per-sensor contributions computed.

### 2.2 Invariants (DET-05)
**Files:** `pipeline/detect/invariances.py`
- 5 evidence rules from SWaT physics bounds; exposed as agent tool later.

**Verification:** invariant checker unit tests on crafted windows.

### 2.3 Attribution + Explanation (XAI-01/-02/-03)
**Files:** `pipeline/explain/attribution.py`, `explanation.py`
- Contribution bars (top-3), evidence object, NL template + LLM polish (prompt-pinned for reproducibility). Explanation path is hypothesis-only: no execution authority, not the C1–C5 validator (PRD §3.4 / AppFlow §2.4).

**Verification:** sample 20 anomaly windows manually reviewed; attribution consistency score computed.

### 2.4 Stress Protocol (EVAL-02) + Fuzzy-Rough Channel Reduction (ROB-01/-02)
**Files:** `eval/stress.py`, `eval/channel_reduction.py`
- Additive noise, sensor zeroing, drift — test distribution only, zero test-time calibration.
- Fuzzy-rough reduced-channel arm: mask fit on TRAIN only; full vs reduced TCN-AE under the **identical** stress protocol (hypothesis language only — reduction % is measured, never assumed).
- Per-arm metrics + mask persisted to `channel_reductions` (ROB-02).

**Verification:** robustness F1 curves vs baseline; reduction table reproducible from config hash.

### 2.5 Explainer Quality Ablation
- EXP-03 variants: with vs. without explanation attached to agent context (no change to detector). Records operator-facing metric proxies (consistency).

**Phase 2 exit criteria:** detector + attribution + explanation on SWaT, baseline vs proposed + stress table.

## PHASE 3 — AGENTIC RAG + VALIDATOR (Weeks 6–8)

### 3.0 Backend Foundation (NEW — AUTH/RBAC/API/migrations; see Tracker P3.0a–g)
**Files:** `app/db/*` (models = hardened Schema v1.1, Alembic 0001/0002),
`app/core/{config,security,logging,exceptions,canonical}.py`,
`app/api/*`, `app/services/*`, `app/workers/main.py`
- AuthN/Z per §14 contract (JWT 15 min + rotating hashed refresh, limiter,
  bootstrap admin); RBAC deps on every route; transactional audit service;
  plan-revision hash binding + immutability trigger; approval/sandbox/agent
  services with conditional state transitions; expiry scheduler + run reaper.
**Verification:** INV battery tests green (hash tamper, expiry race, double
approve/execute, naive lockout, RBAC matrix, refresh rotation/reuse).

### 3.1 KB + RAG + Threat Mapping (RAG-01/-02/-03/-04/-05, TINTEL-01)
**Files:** `pipeline/tintel/mitre_ics.py`, `pipeline/rag/*`
- Build KB: MITRE ATT&CK for ICS (trusted), SWaT docs (trusted), team playbooks (trusted); static mapping table for threat_mappings.
- Rule table + RAG match → `threat_mappings` rows (technique_id, confidence, basis) (TINTEL-01).
- Chunker/embedder/retriever w/ tier metadata; 20 canned QA for RAG-04.

**Verification:** hit-rate / nDCG from `eval/kb_qa.py`.

### 3.2 Agent Loop (AGENT-01..-04)
**Files:** `pipeline/agent/*`
- LangGraph ReAct; tools `query_latest/query_history/search_kb/check_invariant/propose_action`; checkpointing; grounding system prompt.
- Naive variant (AGENT-05).

**Verification:** agent completes 10 seed scenarios with evidence citations; trace viewable.

### 3.3 Validator + Policy (SAFE-01..-04, -08)
**Files:** `pipeline/validator/*` + `configs/policy/*.yaml`
- 5 checks + risk classes; verdict; approval scheduler (**expiry auto-escalate** → `escalated`, never auto-deny).
- Determinism contract (AEGIS-04): C1–C4 deterministic code; C5 rule-based as-deterministic-as-possible; no check uses the planner's model; each check records its `deterministic` flag.

**Verification:** unit tests per check; 30 action fixtures classified correctly.

### 3.4 Injection Suite (EVAL-04, THREAT-01..-04, SAFE-05)
**Files:** `eval/attack_suite/` (families F1–F7)
- 30+ cases: poisoned history, doc manipulation, instruction leakage, narrative social engineering, tool-arg smuggling, hallucination probe.
- F7 cyber-physical family: numeric-only sensor zeroing/bias/scaling on physical channel values (no English text; simulation-only — THREAT-03).
- Attack-the-agent harness invoked on both variants.

**Verification:** per-case pass/fail + ASR/unsafe-action-rate tables.

### 3.5 Sandbox Simulator (SAFE-04)
**Files:** `pipeline/sandbox/plant_model.py`, `simulator.py`
- Lightweight 6-stage SWaT-style surrogate; applies approved actions; emits simulated telemetry deltas.

**Verification:** approval→simulate round-trip integration test (tests/integration).

**Phase 3 exit criteria:** hardened pipeline beats naive on injection suite; approval gate blocks all `control` without human.

## Cross-Phase Constraints

- MUST HAVE items: Phases 1–4 core tasks above; dataset SWaT+WUSTL; detector pair; agent+validator+approval+sandbox; full eval; demo.
- STRETCH GOALS (only after all MUST HAVE green): WADI stress run (DATA-03), LSTM-AE / Transformer-AE / XGBoost ablation (DET-06/-07), gpt-4o-mini cross-model (AGENT-06), SHAP cross-check (XAI-05), approval-vs-safety trade-off analysis.
- Dependencies: 1.4→2.1 (baseline before proposed); 2.1→2.5 (detector before explanation ablation); 3.1→3.2 (KB before agent); 3.2→3.3 (agent before validator integration); 3.4→4.2 (suite before final matrix).
- Risks: SWaT download/licensing delay (mitigate: download in week 1); local LLM latency (mitigate: evidence-only fallback, 90s timeout); stress-test F1 instability (mitigate: report median over 3 seeds); team scope creep (rule: do NOT stack models — stick to named families; Rules.md R30).
- Effort note: heavily weighted toward Phase 3 (validator/injection is the research core).
