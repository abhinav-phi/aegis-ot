# AEGIS-OT — Database Schema

> **Version:** 1.0
> **Last Updated:** 20 August 2026
> **Database:** PostgreSQL 16 (via Docker)
> **Note on storage:** raw telemetry, feature windows, model artifacts, and vector embeddings do **not** live here. This DB stores **metadata, results, agent/validator/approval state, and audit.** Large blobs live in MinIO (raw/features/artifacts) and Chroma (embeddings). See §1.

---

## 1. Storage Ownership Map

| Content | Store | Entity |
|---|---|---|
| Raw telemetry (Parquet) | MinIO `aegis-raw/{dataset}/{run}.parquet` | referenced by `datasets` / `dataset_runs` |
| Preprocessed feature blocks (Parquet) | MinIO `aegis-raw/{dataset}/features/{run}.parquet` | referenced by `dataset_runs.feature_manifest` |
| Model checkpoints | MinIO `aegis-artifacts/{model_version_id}` | referenced by `model_versions.artifact_path` |
| Embeddings / vectors | Chroma (collection per run) | `rag_chunks.chroma_id` |
| Everything else (metadata/results/state/audit) | PostgreSQL | tables below |

## 5. Validator Classifier (check semantics used by API + eval)

| Check | Key | Meaning |
|---|---|---|
| C1 provenance | `validator.filters.provenance` | claims ↔ tool/RAG citations; hostile tier flagged |
| C2 allowlist | `validator.policy_engine.allowlist` | action/target/params ∈ policy grammar |
| C3 pattern | `validator.filters.pattern` | injection markers, encodings, cmd keywords |
| C4 risk class | `validator.policy_engine.risk_class` | read/write/control/forbidden |
| C5 consistency | `validator.policy_engine.consistency` | params vs cited evidence fields |

Determinism (AEGIS-04): C1–C4 are deterministic code; C5 is rule-based entailment / field-match (as deterministic as possible). No validator check runs the planner's model; every check row records `deterministic`.

verdict = soft-min over checks: `forbidden→block`; `control/write unmet→require_approval`; all pass+read→`allow`; persistent inconsistency→`escalate`.
