---

## 1. Product Vision

AEGIS-OT is a **research-grade decision-support system** for SCADA / industrial control networks. It turns raw OT/ICS telemetry into **attributed, explainable anomaly detections**, then uses a **grounded LLM incident-response agent** to propose mitigations that are checked by a **validator / policy gate** and **require human approval** before any simulated action is taken.

The system is explicitly built to answer one research question:

> **RQ1.** Can an LLM-based OT incident-response agent be made trustworthy and safe enough for industrial cybersecurity decision support *under adversarial and misleading inputs*?

The secondary research questions are:

> **RQ2 (exploratory, small-N pilot).** Does adding cyber-physical attribution and natural-language explanation plausibly improve analyst decision quality over a raw detector score? Operationalized as a small, explicitly pilot-scale study (EVAL-08) — reported as exploratory, never as a headline claim.
> **RQ3.** Do validator/policy gating and evidence grounding measurably reduce the unsafe-action rate of an LLM incident-response agent under indirect prompt injection?

AEGIS-OT is **not** marketed as a production-safe product. Every automatic action is simulated; all outputs are decision support for a human analyst in an industrial cyber command center.

### 1.1 Problem Statement

- OT/ICS environments are being integrated into IT-connected operations faster than they can be defended. The December 2025 joint guidance *Principles for the Secure Integration of Artificial Intelligence in Operational Technology* (CISA / ASD's ACSC / NSA AISC, with FBI and international partners) explicitly names LLM-based AI and AI agents as a distinct OT risk category; NIST SP 800-82 Rev. 3 provides the broader OT-security-architecture context that guidance sits within.
- Public anomaly-detection benchmarks on SWaT are largely **saturated**, but the headline numbers (up to ≈98 F1, e.g. TFMAE, ICDE 2024) are typically reported under the **point-adjustment protocol**, which has been shown to overstate performance even for untrained detectors (Kim et al., AAAI 2022). 2026 event-level stress-protocol work (arXiv:2602.15457, preprint) shows **rankings flip** under realistic sensor noise, zeroing, and process drift. AEGIS-OT therefore reports **point-wise F1 and PA%K** and treats stress robustness, not leaderboard F1, as the defensible claim.
- Incident-response LLMs and SOC copilots are being deployed while 2025–2026 preprints (**LogJack** arXiv:2604.15368, **LogInject** arXiv:2607.14493, **Poisoning-the-Watchtower** arXiv:2605.24421, **NetInjectBench** arXiv:2607.10490) demonstrate that **log/telemetry content is an attacker-controlled input**: indirect prompt-injection payloads embedded in logs achieve 0–86% verbatim command execution across models, and existing input-side guardrails largely fail to detect them. All four studies concern IT/cloud/network domains and are cited here as motivating analogy for the OT risk this project measures.
- Existing indirect-prompt-injection agent benchmarks (**InjecAgent**, ACL Findings 2024 — email, finance, smart-home; **AgentDojo**, NeurIPS D&B 2024 — banking, Slack, travel, workspace) do not cover OT/ICS: **no OT/ICS agent benchmark exists**, so a defender cannot measure whether an incident-response agent is safe to deploy in a plant context.
- OT operators cannot trust an autonomous responder, but they also cannot keep up with alert volume. The missing piece is a **demonstrably safe** augmentation layer, not a faster detector.

### 1.2 Solution

A web-based research platform that:

1. **Ingests** public OT datasets (SWaT primary; WUSTL-IIoT-2021 secondary; WADI optional) with temporal, leakage-free splits.
2. **Detects** cyber-physical anomalies with an Isolation Forest baseline and the proposed TCN-AE detector, including **sensor-attribution** (which physical channels drove the anomaly). (LSTM-AE remains only as a stretch ablation, DET-06.)
3. **Explains** each anomaly with sensor-level attribution plus a citeable, natural-language summary grounded in the evidence.
4. **Maps** incidents to MITRE ATT&CK for ICS techniques from OT threat context.
5. **Reasons** using a single ReAct-style planner agent over allowed tools and a **retrieval-augmented knowledge base** (KB): MITRE ATT&CK for ICS, plant documentation, and response playbooks.
6. **Validates** every proposed mitigation through a validator + policy engine (read / write / control / forbidden risk classes).
7. **Gates** every control-class action behind **human approval**, then executes it only inside a **sandbox simulator**.
8. **Demonstrates its own safety claim** with an "Attack the Agent" scenario: a naive agent manipulated by injected context produces an unsafe recommendation; the hardened pipeline detects, grounds, blocks, and re-votes to a safer action.

### 1.3 Research Identity (What AEGIS-OT IS and IS NOT)

AEGIS-OT **is**:
- An anomaly-detection + attribution + explainability study on OT telemetry.
- A measurement study of whether an LLM incident-response agent can be made robust against adversarial inputs.
- A safety-intervention study (validator, policy gate, human-in-the-loop) with measurable outcomes (unsafe-action rate, attack success rate, block rate, approval rate).

AEGIS-OT **is not**:
- A generic IDS or a network-packet-focused NIDS (Competitor 6 / 7 territory).
- A generic LLM chatbot or a multi-agent swarm system (Competitor 5 territory — we use a single planner agent *by design*).
- A claim that LLM diagnosis is ground truth.
- A product that can ever touch a real plant.

**Explanation-pathway boundary (known limitation):** explanation generation (XAI-01/-02) produces a human-readable hypothesis, not a verdict. It is not an execution authority, is not equivalent to the C1–C5 mitigation validator (SAFE-01/-03), and its LLM prompt may cite only the structured attribution + invariant evidence. Unsupported instructions hidden in raw telemetry/log text are never promoted to instructions through this path.

## 5. Success Criteria

| Metric | Target (hypothesis, NOT measured result) |
|---|---|
| Baseline detector F1 (SWaT, evaluation split) | ≥ 0.90 F1 **point-wise** (reported alongside PA%K; never naked point-adjusted F1 — see §1.1; context: SWaT leaderboard ~0.96–0.98 is point-adjusted) |
| Proposed detector F1 ≥ baseline F1 by margin | ≥ +0.01 F1, or equal F1 with strictly better attribution |
| Robustness: proposed detector F1 drop under stress protocol | ≤ 0.10 F1 drop (a key claim — rankings flip otherwise) |
| Naive agent unsafe-action rate (benign scenarios) | ≤ 25% (measured; expected from 2026 log-injection literature 0–86%) |
| Hardened agent unsafe-action rate vs naive | ≥ 60% relative reduction (measured) |
| Validator block rate on injected unsafe actions | ≥ 95% (measured) |
| Attack success rate on hardened agent | ≤ 10% (measured target) |
| RAG citation correctness on canned queries | ≥ 85% (measured) |
| Hallucination rate on unsupported questions | ≤ 10% (measured) |
| Human approval required | 100% of `control` actions (hard requirement) |
| Reproducibility | Every table regenerable from committed configs + data hashes |

Success is **demonstrated via the Experiment Matrix with honest, measured values** — never via inflated claims. See Rules.md R24–R29.

## 6. MVP Scope (Capstone)

1. SWaT + WUSTL-IIoT-2021 ingestion and reproducible pipeline.
2. Isolation Forest baseline and proposed TCN-AE detector with sensor attribution.
3. Evidence-grounded single-agent planner + RAG over MITRE-ICS/SWaT/playbook KB.
4. Validator + policy engine + approval gate + sandbox simulator.
5. Injection suite (7 families F1–F7, 30+ cases) and the "Attack the Agent" demo.
6. Dashboard with telemetry, timeline, attribution, agent/evidence, recommendation, validator, approval UI.
7. Full experiment matrix with metric tables + stress protocol + fuzzy-rough channel-reduction arm (ROB-01/ROB-02).
8. 8-page report-style write-up + demo video + defence deck.

## 7. Stretch Scope

1. LSTM-AE / Transformer-AE / XGBoost ablation variants (DET-06 / DET-07).
2. WADI stress-only run (DATA-03).
3. SHAP cross-check on windows (XAI-05).
4. Cross-model robustness (gpt-4o-mini) (AGENT-06).
5. Approval-rate vs. safety trade-off analysis on the mitigation enforce/veto spectrum.

## 8. Explicit Non-Goals

- Connecting to, or controlling, any real SCADA/PLC/plant equipment.
- Real-time production deployment or 24×7 operation.
- Network-packet-level NIDS (that is Competitor 6/7 territory).
- A general-purpose SOC tool spanning IT and OT.
- Multi-agent orchestration (Comp 5) — a single planner is an architectural decision, not a shortcut.
- Blockchain, distributed training, or federated learning (see Competitor 7/9).
- Claiming "state of the art" on SWaT: detection F1 is already saturated; our measurable contribution is attribution + robustness + safe agent evaluation.
